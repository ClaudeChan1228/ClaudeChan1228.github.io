SAP PO REST接口返回映射报错：Content is not allowed in prolog 解决方案

本文最后更新于 2026-07-29

问题背景

在 SAP PO 中配置 SOAP to REST 接口时，接口测试调用失败，需要排查并解决映射相关问题。

问题现象

错误信息

在 SAP PO Monitor 中查看消息监控日志，发现以下错误信息：

关键错误提示：Content is not allowed in prolog.

初步观察

通过 Monitor 查看消息流，发现一个重要线索：

  • REST Receiver Communication Channel (CC) 正常返回了 JSON 格式的响应数据
  • 错误发生在映射处理阶段，而非 REST 调用本身

问题分析

错误原因

“Content is not allowed in prolog” 是 XML 解析时的典型报错，通常表示：

  • XML 解析器在文档序言（prolog）之前遇到了非法内容
  • 或者试图将非 XML 格式的数据按 XML 格式解析

根本原因定位

结合错误现象，问题根源在于：

  1. REST 接口返回的是 JSON 格式数据
  2. SAP PO 的映射程序（Message Mapping / Operation Mapping）处理的是 XML 格式数据
  3. REST Receiver CC 在接收到 JSON 响应后，没有将其转换为 XML，直接传递给映射程序
  4. 映射程序尝试解析 JSON 字符串作为 XML，触发 “Content is not allowed in prolog” 错误

解决方案

配置步骤

需要在 REST Receiver Communication Channel 的 Response Format 配置区域进行以下设置：

1. 设置响应数据格式

  • Data Format: 选择 JSON

2. 启用 JSON 到 XML 转换

  • 勾选 “Convert to XML” 选项

这是解决问题的关键配置：启用此选项后，REST Adapter 会自动将 JSON 响应转换为 XML 格式，然后再传递给后续的映射程序。

3. 配置 Wrapper Element（可选但推荐）

为了让转换后的 XML 结构更规范，建议配置包装元素：

  • 勾选 “Add Wrapper Element”
  • Element Name: 设置根元素名称（例如：MT_***_RESPONSE_ES）
  • Element Namespace: 设置命名空间 URL（与 ESR 中定义的消息类型命名空间一致）

4. 指定 ESR 映射对象

在 Message Mapping 或 Operation Mapping 中：

  • 确保响应消息类型定义的 XSD 结构与 JSON 转换后的 XML 结构匹配
  • 如果使用了 Wrapper Element，XSD 根节点需要与配置的 Element Name/Namespace 一致

验证结果

配置完成后：

  1. 重新测试接口调用
  2. 在 Monitor 中观察消息流：
    • REST Receiver CC 接收 JSON 响应
    • 自动转换为 XML 格式
    • 映射程序正常处理 XML 数据
  3. 消息处理成功，不再出现 “Content is not allowed in prolog” 错误

经验总结

关键要点

  1. 数据格式转换必须在 CC 层完成：不要试图在映射程序中处理 JSON 字符串
  2. “Convert to XML” 是核心开关：REST Adapter 的 JSON/XML 转换依赖此配置
  3. 响应消息与 ESR 结构一致：转换后的 XML 结构必须与 ESR 中定义的响应消息类型匹配

排查思路

遇到类似 “Content is not allowed in prolog” 错误时：

  1. 先确认数据格式：源端返回的是 JSON 还是 XML？
  2. 检查 CC 配置：是否启用了必要的格式转换？
  3. 查看 Monitor 日志：在哪个阶段失败？数据流转到哪一步？
  4. 验证 ESR 定义：消息类型结构是否与实际数据匹配？

适用场景

此解决方案适用于以下场景：

  • SOAP to REST 接口（同步调用）
  • REST 接口返回 JSON 格式数据
  • 需要在 SAP PO 中对响应数据进行 Message Mapping
  • 使用 REST Receiver Communication Channel
