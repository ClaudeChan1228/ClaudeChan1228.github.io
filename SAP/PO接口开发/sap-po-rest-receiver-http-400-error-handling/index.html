SAP PO REST Receiver Adapter 处理 HTTP 400 错误返回报文

本文最后更新于 2026-08-17

问题背景

在 SAP PO 中配置 SOAP2REST 接口调用第三方系统时，遇到一个特殊场景：

  • 对方系统在业务处理失败时返回 HTTP 400 状态码
  • 同时在响应报文中返回了详细的错误信息（如错误代码、错误描述等）

按照标准的 RESTful API 设计原则，业务处理失败应该返回 HTTP 200，然后通过报文体中的业务状态码来标识成功或失败。但实际对接中，有些系统会在请求格式正确但业务校验失败时直接返回 4xx 错误码。

问题分析

SAP PO 的默认行为是：

  • 当接收到 HTTP 4xx 或 5xx 错误状态码时，会将该响应视为异常
  • 异常情况下，SAP PO 不会继续解析返回报文
  • 这导致对方系统返回的业务错误信息丢失，无法在 SAP ABAP 程序中获取和处理

这种情况下，虽然知道接口调用失败了，但无法得知具体的失败原因，给问题排查和业务处理带来困难。

解决方案

通过在 REST Receiver Adapter 的 Error Handling 标签页配置自定义结果处理器，可以将 HTTP 400 响应当作正常报文接收。

配置步骤

  1. 打开 SAP PO Integration Directory，进入对应的 Receiver Communication Channel

  2. 切换到 Error Handling 标签页

  3. 配置 Result Handler 如下：

    配置项 配置值 说明
    Source Exception 表示处理异常情况
    Action Custom Result 自定义结果处理
    Message Content {http_result} 使用 HTTP 返回的原始报文作为消息内容

  4. 不要勾选 “Selection does NOT match” 选项

配置效果

配置完成后：

  • SAP PO 会将 HTTP 400 响应作为正常消息处理
  • 返回的报文会按照 ESR 中配置的 Response Data Type 进行解析
  • 在 SAP ABAP 程序中可以通过 Proxy 或 Mapping 正常获取到返回报文内容
  • 可以从报文中提取业务错误代码、错误描述等信息进行后续处理

技术要点

1. {http_result} 变量

{http_result} 是 SAP PO 提供的动态变量，表示 HTTP 响应的原始报文内容。在 Error Handling 中使用该变量，可以确保即使 HTTP 状态码为错误码，报文内容也不会丢失。

2. 适用场景

这种配置方式适用于以下场景：

  • 对方系统在业务校验失败时返回 4xx 状态码
  • 错误响应报文结构与正常响应报文结构一致（或者有专门的 Error Response DT）
  • 需要在 SAP 端解析并处理详细的错误信息

3. ESR 配置要求

在 ESR (Enterprise Services Repository) 中需要确保：

  • Response Message Type 的结构能够包容错误响应的字段
  • 或者配置独立的 Fault Message Type 来接收错误响应

注意事项

  1. 不要滥用：这种配置会将 HTTP 错误当作正常消息处理，可能会掩盖真正的网络或服务异常。建议只针对特定的 HTTP 状态码（如 400）配置，不要对所有错误码一刀切。

  2. 监控和日志：配置后建议在 Message Mapping 或 ABAP Proxy 中添加日志记录，区分正常响应和错误响应，便于后续监控和问题排查。

  3. 与第三方系统协调：从长远看，建议与第三方系统协调，让其遵循标准的 RESTful 设计原则，业务错误返回 200 状态码，通过报文体中的状态码区分成功和失败。

配置界面说明

在 SAP PO Integration Directory 的 Receiver Communication Channel 配置界面中：

关键配置说明：

  • Error Handling 标签页：位于配置界面顶部的标签栏最右侧
  • Result Handler 区域：在 Error Handling 标签页的主要配置区域
  • Source 下拉框：选择 “Exception” 表示处理异常情况
  • Selection does NOT match 复选框：保持不勾选状态
  • Action 下拉框：选择 “Custom Result” 表示自定义结果处理
  • Message Content 文本框：输入 {http_result} 变量

总结

通过在 SAP PO REST Receiver Adapter 的 Error Handling 中配置自定义结果处理器，可以有效解决第三方系统返回 HTTP 错误码但同时包含业务错误信息的场景。这种配置方式在实际项目中非常实用，能够确保错误信息不丢失，提高问题排查效率和业务处理能力。
